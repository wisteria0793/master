# Phase 5推薦エンジンへの景観（NKDE近似）目的関数の追加

## 背景と目的
現在の多目的最適化ルート推薦（Phase 5）では、「移動距離（最小化）」「Google評価（最大化）」「レビュー数（最大化）」の3つの目的関数を使用しています。
ここにユーザーからの要望である「景観の良さ（NKDE: ネットワークカーネル密度推定の概念を応用した指標）」を4つ目の目的関数として追加し、景観の優れた場所をより優先的に推薦できるようにします。

## 設計方針
ルート探索時（`router.py`）に行う厳密なNetwork KDEを、最適化のループ内（数万回の評価が発生する）で計算するのは計算コストが大きすぎるため、Phase 5の候補抽出段階で**「起点と同じ景観クラスタに属する景観ポイントの密集度（Euclidean KDE近似）」**を各候補POIについて事前計算し、これを「景観の良さ（Landscape Score）」として最大化するアプローチをとります。

## 変更内容

### 1. `src/urban_analysis/prototype/phase5_recommender.py` の修正

#### (1) 景観スコアの計算と正規化処理の追加
*   `recommend` メソッド内で `super().recommend()` を呼んだ直後に、対象の景観クラスタ（`target_ls_cluster`）に属する景観ノード群を取得します。
*   各候補POIに対して、半径500mのQuarticカーネルを用いた空間密度スコア（`ls_density`）を計算します。
*   スコアを0〜1に正規化（`norm_ls_density`）し、`candidates` データフレームに追加します。

#### (2) 目的関数の4次元化
*   `_objective_function` を変更し、4つ目の戻り値として `-mean_ls_density`（負にすることで最小化問題として扱う）を追加します。
*   `MultiObjProblem` クラスの初期化で `n_obj=4` に変更します。

#### (3) NSGA-III のパラメータと重みの更新
*   デフォルトの重み設定を更新し、4つの指標でバランスを取ります。
    *   旧: `distance: 0.5, rating: 0.3, review_count: 0.2`
    *   新: `distance: 0.4, rating: 0.2, review_count: 0.2, landscape: 0.2` (configで指定がない場合)
*   `get_reference_directions` の引数を `n_dim=4` に変更し、適切な `n_partitions` (例: 7 -> 参照点120個) を設定します。
*   最終解選択のスコア計算（内積）に `landscape` の重みと結果を反映し、結果の辞書にも `mean_landscape` を出力するようにします。
