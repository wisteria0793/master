# 実装計画: 景観クラスタに基づく観光ルート推薦プロトタイプ

## 1. 目的と概要
StreetCLIPとGNNを用いて抽出された「景観の特徴（クラスター）」を活用し、ユーザーが選択した基準となる観光施設（POI）と「距離的・意味的（景観的）に近い」施設を推薦し、それらを巡るルートを生成・可視化するシステムのプロトタイプを構築する。

## 2. システム要件と前提
- **入力データ**:
  - POIの基本情報（座標、名称など）
  - 各POIが紐づく景観クラスター情報（実験14/15で生成済みのエンベディングから算出されたクラスタID）
  - 道路ネットワークデータ (OSM)
- **出力**:
  - インタラクティブなマップ表示機能 (Folium)
  - 選択されたPOIを中心とした推薦POIと、それらを結ぶルート

## 3. 処理パイプラインの全体像

### Step 1: データの統合と準備 (Data Preparation)
- **タスク**: 既存のクラスタリング結果（景観クラスター）とPOI情報を紐付ける。
- **入力**: 
  - POI座標・基本情報 (`.csv` 等)
  - 景観クラスターの学習済みエンベディングまたはクラスターID (`.csv` 等)
- **出力**: 統合された `poi_with_clusters.csv` のような紐付けデータ

### Step 2: 推薦ロジックの実装 (Recommendation Engine)
- **タスク**: 基準POIを入力としたとき、推薦すべきPOIのリストを返す関数を作成する。
- **ロジック**:
  1. 基準POIのクラスタIDを取得。
  2. 同じクラスタIDを持つPOIを候補として抽出（景観的・意味的フィルタリング）。
  3. 距離フィルタリング: 基準POIから歩行圏内（例: 直線距離またはネットワーク距離で半径1.5km以内）のものに絞る。
  4. (オプション実装) 抽出されたPOI間で、エンベディングのコサイン類似度が高い上位N件（例: 3〜5件）にソート・限定する。

### Step 3: ルート探索機能の実装 (Routing)
- **タスク**: 上位のPOIを繋ぐ移動ルートを算出する。
- **ツール**: `osmnx` (Pythonパッケージ)
- **ロジック**:
  - 対象エリアの道路ネットワークグラフを利用する。
  - 選定された複数のPOI間で最短経路（歩行用）を計算する。プロトタイプ段階では、基準POIから最も近いPOI順に経由するような単純な経路、もしくは簡易的な巡回経路を生成する。

### Step 4: UI/可視化の構築 (Visualization)
- **タスク**: 選ばれたPOIと生成されたルートを地図上にプロットするスクリプトを作成する。
- **ツール**: `folium` (HTML出力用ライブラリ)
- **出力仕様**: 
  - 基準POIを「赤色の独自のアイコン（星など）」で強調表示。
  - 推薦されたPOIを「青色のピン」で一覧表示。
  - プロットされたPOIを繋ぐルートを線画で描画したインタラクティブなマップ。

### Step 5: Network KDEの統合と景観ルート最適化 (KDE Routing)
- **タスク**: 景観クラスタのホットスポットを通るように経路探索のコスト関数を最適化する。
- **入力**: 対象POIの所属クラスタID、事前構築済みの歩行者用道路グラフ。
- **ロジック**:
  1. API制限回避のため、対象エリアの道路グラフを事前にキャッシュ（`.graphml`）から読み込む構造にする。
  2. ルート探索時に、基準POIと同じクラスタに属するStreet View地点を用いて、対象サブグラフ上で Network KDE を計算しエッジの密度を出す。
  3. 各エッジに `cost = length / (1 + α * density)` というカスタム重みを割り当てる。
  4. カスタム重みを元にしたダイクストラ法により、少し遠回りしてでも景観の文脈を反映したルートを探索する。

### アルゴリズム詳細: Network KDEによる景観経路探索の計算式
Network KDEを用いて「景観が良い」という事象を定量化し、最短経路探索アルゴリズム（Dijkstra法）のコストに反映させる一連の処理ロジックです。

**1. 影響の伝播（カーネル関数）**
`KDE_BANDWIDTH_M`（500m）以内の道路ネットワークに対し、ターゲットと同じ景観クラスタに属する地点からの影響度を以下のクォーティック（四次）カーネル関数で伝播させます。
- `kernel_val = (1 - (dist / KDE_BANDWIDTH_M)^2)^2`
  - 距離 `dist = 0m` のとき、影響度は `1.00`
  - 距離 `dist = 250m` のとき、影響度は `0.56`
  - 距離 `dist = 500m` 以上のとき、影響度は `0.00`

**2. 道路（エッジ）ごとの密度算出**
対象の交差点（ノード）に蓄積されたすべての影響度を合計し、道路の両端ノードの平均値を取ったのち「実際の道路の長さ」で割ることで、**その道路1mあたりにどれだけ景観要素が詰まっているかという純粋な密度（`density`）** を計算します。
（※極微小な景観の変化も捉えるため、密度による一律のゼロカット（閾値）は設けていません）

**3. カスタムコスト関数（景観割引）の適用**
各エッジに対し、Dijkstra探索用の新しい重み（コスト）を設定します。
- `custom_cost = length / (1.0 + KDE_ALPHA * density)`
- ここで `KDE_ALPHA = 10.0` の場合、密度が `0.4` の道路はコストが長さの `1/5` まで割引されます。
- システムは物理距離ではなくこの「割引されたコスト」が最小になる道を繋いでいくため、自動的にホットスポットを周回する景観ルートが導出されます。

## 4. プロトタイプのディレクトリ・ファイル構成案 (src/urban_analysis 配下)
```text
prototype/
├── __init__.py
├── data_loader.py       # Step 1: データの読み込み・結合処理
├── recommender.py       # Step 2: 推薦ロジック（距離・クラスタフィルタなど）
├── router.py            # Step 3: OSMnxによるルート探索
└── visualize.py         # Step 4: Foliumによるマップ描画
```

## 5. 定数・パラメータ一覧 (Constants & Parameters)
プロトタイプ内で使用・調整可能な主なパラメータの一覧です。

| 変数名 / 定数名 | デフォルト値 | 説明 | 使用ファイル |
| :--- | :--- | :--- | :--- |
| `N_CLUSTERS` | `20` | 景観特徴のクラスター数。 | `data_loader.py` |
| `DISTANCE_THRESHOLD_M`| `1500` | 推薦対象とする徒歩圏内の最大半径（メートル）。 | `recommender.py` |
| `TOP_N_RECOMMENDATIONS`| `3` | 最終的に推薦・ルート接続する施設の数。 | `recommender.py` |
| `ROUTING_NETWORK_TYPE`| `'walk'`| ルート検索に使用する道路ネットワークの種別（歩行者用）。 | `router.py` |
| `ROUTING_RADIUS_M`   | `2000` | 経路探索用グラフを取得する際の起点からの半径（距離閾値＋余裕分）。 | `router.py` |
| `OUTPUT_MAP_DIR`     | `docs/prototype_route_system/` | HTMLマップファイルの出力先ディレクトリ（各POI名が含まれる）。 | `run_prototype.py` |
| `KDE_BANDWIDTH_M`    | `500`  | Network KDE計算時に影響範囲を決めるカーネルのバンド幅（メートル）。 | `router.py` |
| `KDE_ALPHA`          | `10.0` | 距離と景観密度のトレードオフを調整する係数（大きいほど遠回りしてでも景観優先）。 | `router.py` |
| `CACHED_GRAPH_PATH`  | `data/processed/osm/hakodate_walk.graphml` | OSMから事前に保存するローカルキャッシュ用道路ネットワークグラフのパス。 | `router.py` |
