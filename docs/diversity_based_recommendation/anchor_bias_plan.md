# Phase 4.1: 起点テーマを尊重した「重み付け」多様性フィルター

非常に鋭く、システムの本質を突くご指摘です。
「居酒屋」を起点に選んだユーザーは、多様性を求めているとはいえ「飲み歩き」がメインテーマであるはずです。それを他の機能（カフェ、史跡など）と完全に平等（上限2件ずつ）に扱ってしまうと、**「そもそも何のためにその施設を起点に選んだのか？」というユーザーの意図（Core Intent）が薄れてしまいます。**

この問題を解決するため、多様性フィルターに**「起点の機能クラスタに対する優遇枠（傾斜配分）」**を導入する改修を提案します。

## 提案するアルゴリズムの変更 (Anchor-Biased Diversity)

`phase4_recommender.py` のフィルターロジックを以下のように変更します。

1. **起点POIの機能クラスタ（メインテーマ）の上限枠を増やす**
   - 起点と同じ機能クラスタ: **上限 4件** （全体の40%程度を占める主役に据える）
2. **それ以外の機能クラスタ（サブテーマ）の上限枠を絞る**
   - 起点と異なる機能クラスタ: **上限 1〜2件** （あくまで休憩やアクセントとして扱う）

### 具体的なルートの構成イメージ
「旧函館区公会堂（史跡）」を起点として Top 10 を選ぶ場合：
- **史跡・歴史的建造物（起点と同じ機能）**: 4件 （メインの観光）
- **カフェ・スイーツ（別機能）**: 2件 （途中の休憩）
- **お土産・物販（別機能）**: 2件 （買い回り）
- **公園・景勝地（別機能）**: 2件 （散策）
※合計10件

## 期待される効果
これにより、**「起点のテーマ（ユーザーの強い興味）を軸に据えつつ、それに付随する他の活動（飲食・購買）をバランス良く添える」** という、観光学や行動心理学において最も理想的な「テーマ性を持った回遊行動」がシステム上で表現できるようになります。
