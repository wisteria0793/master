# 多様性を考慮した観光ルート推薦の改善計画

ご指摘いただいた「地域の特性の考慮」と「観光客の行動心理（機能の多様性）」に対する本質的な課題を解決するための実装計画です。

## 課題の整理
1. **地域の特性の考慮**:
   - 現在のシステムですでに活用している「景観クラスタ（GNN）」は、単なるテキストではなく「周辺の建物の形状や配置、道路網」といった空間文脈を学習したものです。つまり、「同じ景観クラスタに属する」ということは**「同じような街の雰囲気・コンテキスト（地域の特性）を共有している」**ことを意味しています。
2. **機能の偏りと行動心理**:
   - 現在は「機能クラスタ」まで完全一致させているため、「史跡だけ」「カフェだけ」という極端なルートになってしまっています。
   - 実際の観光客は「史跡を見て、カフェで休み、お土産を買う」というように、**一定のテーマ（景観・雰囲気）の中で多様な機能を回遊する**のが自然な行動心理です。

## 提案する変更内容 (Proposed Changes)

この行動心理をシステムに反映させるため、`phase3_recommender.py` の推薦ロジックを以下のように改修します。

### 1. 絞り込み条件の緩和（景観ベースへの移行）
- **変更前**: `機能クラスタ == 起点` AND `景観クラスタ == 起点`
- **変更後**: `景観クラスタ == 起点` のみに緩和します。
- これにより、「同じ機能の施設」ではなく、「起点と同じ雰囲気（地域の特性）を持つエリア内のあらゆる施設」が候補に挙がるようになります。

### 2. 機能の多様性（Diversity）を担保したピックアップ
単純に「景観が同じで距離が近い順」に上位10件を取得すると、たまたま近くに密集している同じ種類の施設（例: 飲食店ばかり）に偏るリスクがあります。これを防ぐため、抽出時に**「同じ機能クラスタの施設は最大 N 件までしか選ばない」**という多様性フィルター（Diversity Filter）を導入します。

#### 具体的なアルゴリズムの流れ
1. 起点と同じ「景観クラスタ」を持つPOIをすべて抽出する（これが「地域の特性」を共有する候補プール）。
2. 起点からの距離が近い順にソートする。
3. リストを上から順番に見ながらルートに追加していくが、**「すでにルートに同じ機能クラスタの施設が 2件（上限値は調整可能） 含まれている場合は、その施設はスキップする」**。
4. これを繰り返し、合計10件（または上限）に達するまで多様な機能の施設を拾い上げる。
