# 実験17: GNNにおける時間的特徴（営業時間・営業日）の反映強化計画

現状の分析（実験17）において、営業時間や営業日を統合しているにもかかわらず、クラスタリング結果に大きな変化が見られず、朝市（朝）と駅前居酒屋（夜）が同じクラスタに分類されてしまう課題を解決します。

## 課題の分析
1. **特徴量の次元不均衡**:
   テキスト埋め込み（768次元）に対し、時間的特徴（31次元）が圧倒的に少なく、ベクトル間の距離計算において時間軸の違いが無視されやすくなっています。
2. **グラフ構造の意味不足**:
   エッジ（繋がり）が物理的距離（500m）のみに基づいているため、近くにある施設は活動時間が全く異なっても強引に「スムージング」され、特徴が同質化してしまいます。

## 提案する修正内容

### 1. 時間的特徴量への重み付け（Temporal Scaling）
時間的ベクトル（31次元）に対してスケーリング係数（$\alpha$）を導入し、学習時に時間軸の違いをより「強調」されるようにします。

#### [MODIFY] [train_poi_gnn.py](file:///Users/atsuyakatougi/Desktop/master/src/urban_analysis/gnn/train_poi_gnn.py)
- `TEMPORAL_WEIGHT` 定数を導入（初期値: 10.0〜20.0程度）。
- `temp_feat` を連結する前に、この重みを乗算します。

### 2. グラフ構造への「同時性（Simultaneity）」の導入
エッジの生成条件を「地理的近接」だけでなく「活動時間の重複」も考慮するように変更するか、エッジに「同時性」の重みを付与します。

#### [MODIFY] [graph_builder.py](file:///Users/atsuyakatougi/Desktop/master/src/urban_analysis/gnn/graph_builder.py)（または `train_poi_gnn.py` の内部ロジック）
- 物理的に近くても、営業時間が全く重ならない施設間のエッジを弱める、あるいは削除します。
- これにより、朝市コミュニティと深夜居酒屋コミュニティがグラフ上で物理的に「繋がりにくい」状態を作ります。

## 期待される効果
- 朝市（5時-12時）と居酒屋（18時-26時）の埋め込みベクトルが空間的に大きく離れ、異なるクラスタに分離される。
- 「時間帯による都市の使い分け」をより明確に反映したクラスタマップが生成される。

## 検証方法
1. 重みを付けた状態でGNNを再学習。
2. `analyze_poi_gnn_clusters.py` を実行し、朝市と駅前居酒屋が別のクラスタIDに割り当てられているか、地図上で確認する。

## オープンな質問
- **重みの強さ**: まずはテキスト次元の寄与度に近づけるため、10倍程度の重みからテストしますが、適宜調整が必要かもしれません。
- **エッジの削除**: 極端に営業時間が重ならない場合（例：Jaccard係数 0.1以下）にエッジを削除してしまっても良いでしょうか？それともエッジに強弱（Weight）を付ける方が自然でしょうか？
