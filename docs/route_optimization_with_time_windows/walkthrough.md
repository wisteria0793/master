# ルート生成最適化（営業時間考慮・TSPTW） 完了レポート

## 概要
フェーズ3におけるルート生成アルゴリズムを拡張し、各施設の**営業時間（Time Window）**を考慮した厳密なスケジューリングを行えるようにしました。これにより、訪問時に施設が閉まっている事態を防ぎ、より現実的で効率的な観光ルートが提案されます。

## 変更内容

### 1. 営業時間の抽出と解析 (`src/urban_analysis/prototype/time_parser.py`)
- Google Places APIの日本語文字列（例: `11:00～15:00`）から正規表現を用いて開店時間と閉店時間を抽出するモジュールを新規作成しました。
- 抽出した時間は `0`〜`1440` の分単位（0時からの経過時間）に変換され、各施設に時間枠が設定されます。

### 2. データフレームへの統合 (`phase3_recommender.py`)
- POIデータを読み込む際に `time_parser.py` を呼び出し、各POIに対して `open_time` と `close_time` を付与しました。

### 3. TSPTW（時間枠付き巡回セールスマン問題）のオリエンテーリング的拡張 (`router.py`)
- 従来の制約なしの Held-Karp (DP) を、時間枠の枝刈りを伴う深さ優先探索（DFS Branch & Bound）アルゴリズム `_solve_tsptw_dfs` にリプレイスしました。
- 徒歩速度を秒速約1.2mに設定し、OSMの道路ネットワーク距離から**移動時間**を計算するようにしました。
- **スキップ処理の導入**: 各施設に一定時間（デフォルト30分）滞在する前提で、到着時刻が閉店時間を過ぎる場合や、**開店までの待機時間が30分を超える場合**はその施設を「スキップ」するように変更しました。これにより、夜しか開いていないお店などに昼から無理に長時間滞在（待機）するのを防ぎます。
- 最終的に算出されるルートは、パレート支配による枝刈りを利用し「最も多くの施設を訪問でき、かつ景観コスト（NKDEコスト）が最小」となる現実的なルートとなります。

### 4. 実行インターフェースと出力の改善 (`run_phase3.py`)
- CLI引数として `--time` を追加し、ユーザーが出発予定時刻（例: `10:00`）を指定できるようにしました。
- コンソールおよび出力されるHTMLマップ（Foliumのポップアップ）にて、各施設への**到着予定時刻・待機時間・出発予定時刻**を確認できるようになりました。
- **スキップ通知とファイル名連番**: 営業時間外等でスキップされた施設がある場合は `※ 営業時間外の施設を 3 件スキップしました。` のように表示し、マップ出力ファイルが既存のものと被る場合は `_1`, `_2` のように自動で連番を振る処理を追加しました。

## 検証結果
`run_phase3.py 函館朝市 --time 10:00` を実行し、以下の通り時間が正確にトラックされることを確認しました。
```text
--- 推薦ルート スケジュール ---
 1. [10:00 -> 10:00] 元祖活いか釣堀（函館朝市イカ釣り体験）
 2. [10:01 -> 10:31] 朝市食堂　二番館
 3. [10:32 -> 11:02] 一花亭　たびじ
 ...
12. [15:03 -> 15:03] 元祖活いか釣堀（函館朝市イカ釣り体験）
```
時間が順に加算されており、指定した時刻通りにルート生成が最適化されています。
