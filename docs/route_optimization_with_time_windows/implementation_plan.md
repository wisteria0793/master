# ルート生成最適化の実装計画（営業時間・時間枠の考慮）

現在のフェーズ3のルート生成には以下の課題があります。
1. **営業時間の無視**: 訪問時に施設が閉まっている可能性がある。
2. **近隣POIの貪欲な選定**: 起点から単に物理的距離が近い上位10件を自動で選んでいるため、体験の質や時間的効率が最適化されていない可能性がある。

これらを解決し、より「効率的で実用的なルート」を生成するためのアプローチを提案します。

## Proposed Changes

### 1. データ拡張：営業時間のパースと時間枠（Time Window）の付与
生の `data/raw/output_with_google_places_jp.json` には日本語の `hours` フィールド（例: "11:00～15:00"）が存在します。
- **実装内容**: `hours` 文字列から正規表現を用いて「開店時間」と「閉店時間」を抽出し、時間枠 `[open_time, close_time]` を各POIに付与するモジュールを実装します。

### 2. 候補選定（Selection）の高度化：時間的・体験的なスコアリング
単に距離が近い10件を選ぶのではなく、「訪問可能な時間帯」を考慮して候補を選びます。
- **実装内容**:
  - ユーザーの「出発時間（例: 10:00）」を受け取れるようにします。
  - 営業時間外の施設、あるいは移動時間を含めると訪問が不可能な施設を初期フィルタリングで除外します。

### 3. ルート探索（Routing）の高度化：時間枠付き巡回セールスマン問題（TSPTW）
現在の Held-Karp（動的計画法によるTSP）を拡張し、営業時間を考慮したルート探索を行います。
- **実装内容**:
  - `dp[(mask, last_node)]` に「その状態における最小の到着時刻」を保存するように DP を変更します。
  - 施設到着時に開店前なら「開店まで待機（時刻を進める）」、閉店後なら「その経路は無効（Infinityコスト）」として枝刈りします。
  - 景観コスト（NKDEコスト）と移動時間コストを統合した評価関数で最適な順番を決定します。
